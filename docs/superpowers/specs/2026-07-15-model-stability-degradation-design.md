# 模型稳定性与降级设计

## 目标

统一保护 `scenic-guide` 对外部模型的调用，避免网络抖动、供应商限流、超时或服务异常导致游客问答整体不可用。保护范围包括 Chat 非流式与流式调用、通用聊天、查询改写/重排、Embedding 和多模态调用。

## 设计

- 每个 Provider 使用进程内保护器，默认单次调用超时 60 秒，网络错误、超时和 5xx 最多重试 2 次；4xx、鉴权失败和参数错误不重试。
- 连续 3 次可重试失败后熔断 30 秒；熔断期间不发起上游请求，半开状态只允许一次探测请求。
- RAG 非流式请求使用查询级并发去重；缓存命中直接返回，未命中的相同请求只允许一个上游调用。
- 景区问答模型失败时使用已经检索到的知识块生成本地回答；没有证据时返回明确拒答。Embedding 失败时退回 BM25，多模态失败时保留文字输入能力并返回可识别的服务不可用错误。
- Prometheus 记录 Provider 调用次数、成功/失败/超时、重试、熔断和延迟直方图；标签只使用固定 Provider 名称和结果类型。
- 健康接口返回 RAG Chat、Embedding 和保护器状态；不记录 API Key、请求体或完整游客原文。

## 测试验收

- 上游超时或 5xx 时按策略重试，4xx 不重试。
- 连续失败后进入熔断，熔断期间不触发上游请求，冷却后可半开恢复。
- 同一查询并发请求只触发一次上游调用。
- Chat 失败可由本地知识库回答，空知识时正确拒答；Embedding 失败可用 BM25；多模态失败不泄露上游响应体。
- 现有 RAG、数字人和多模态回归测试保持通过。
