# P0：Qwen Omni、数字人运行时、评测与消费分析实施计划

## 范围

本轮实现方案 A 的以下内容：

- Qwen Omni 多模态旁路；
- 管理端数字人配置到游客端 TTS/音量/情绪/Live2D 的运行时链路；
- 最终回答准确率和真实延迟评测；
- 语音转写到回答、TTS 首字节和完整音频的延迟基准；
- 官方 Excel 消费行为聚合和管理员分析接口。

本轮暂不实现游客情绪提取修正，不修改 `Open-LLM-VTuber` 核心代码，不替换普通文本 RAG 主链路。

## 依赖关系

```text
配置与多模态客户端
        │
        ├── 多模态 API
        │
数字人配置运行时映射 ── 游客端 TTS/音量/形象
        │
准确率评测 ── 现有文本问答 API
语音延迟基准 ── 数字人语音转写 API + TTS API
消费聚合文件 ── 管理员消费分析 API/页面
```

## Phase 1：多模态配置和 API

### Task 1：增加 Qwen OpenAI 兼容配置与客户端边界

**描述：** 增加启用开关、provider、model、base URL、超时和环境变量 API Key；将上游调用封装为独立服务，不让 Key 进入数据库、响应或日志。

**验收标准：**

- [ ] 未启用或缺少配置时，普通 RAG 行为不变；
- [ ] 启用时校验必填配置，日志不输出 Key；
- [ ] 上游超时、非 2xx 和无效响应能返回分类错误。

**验证：** Go 单元测试、`go test ./internal/config ./internal/service`、`go vet ./...`。

**依赖：** 无。

**预计文件：** `internal/config/`、`internal/service/`、配置模板和对应测试，控制在 5 个以内。

### Task 2：新增多模态聊天接口

**描述：** 新增 multipart 请求接口，支持文本、图片、音频、视频白名单、大小/时长限制和临时文件清理；无媒体时不影响 `/api/v1/ai/chat`。

**验收标准：**

- [ ] 文本或媒体至少存在一个；
- [ ] MIME、文件头、大小和媒体数量校验生效；
- [ ] 成功响应包含 `response`、`model`、`modality`、`trace_id`、`degraded`；
- [ ] 上游不可用时不伪造模型回答。

**验证：** Handler 单元测试、请求边界测试、`go test ./...`。

**依赖：** Task 1。

**预计文件：** 多模态 handler/service、路由、测试，控制在 5 个以内。

## Phase 2：数字人运行时配置

### Task 3：扩展数字人配置和安全运行时接口

**描述：** 在现有 `DigitalHumanConfig` 上增加实际 `voice_id`、可选 `tts_rate` 和运行时版本字段，补充范围校验、默认值和游客端安全配置接口。

**验收标准：**

- [ ] 旧记录自动使用兼容默认值；
- [ ] voice ID、语速、音量、情绪强度和头像 ID 均经过服务端校验；
- [ ] 游客端接口不返回管理字段或任何密钥；
- [ ] 管理接口回归测试保持通过。

**验证：** Model/service/handler 测试，`go test ./internal/model ./internal/service ./internal/handler`。

**依赖：** 无。

**预计文件：** 模型、service、handler、路由和测试，控制在 5 个以内。

### Task 4：游客端应用 TTS、音量、默认情绪和头像配置

**描述：** 游客端加载运行时配置，TTS 不再固定使用单一 voice；将语速映射为 Edge TTS rate，将音量映射到播放器，将默认情绪和头像用于初始化和兜底。

**验收标准：**

- [ ] 后台修改 voice/rate 后，下一次 TTS 请求使用新值；
- [ ] 音量不会被错误传给 TTS voice 参数；
- [ ] 配置加载失败时保留当前默认行为；
- [ ] 头像仍经过现有白名单和用户偏好逻辑。

**验证：** 前端类型检查、lint、相关组件测试、`npm run check`、`npm run lint`、`npm run build`。

**依赖：** Task 3。

**预计文件：** `DigitalHumanView.vue`、TTS/audio 服务、API 类型和中英文案，控制在 5 个以内。

## Phase 3：准确率与语音延迟评测

### Task 5：重写最终回答准确率评测脚本

**描述：** 修复 `scripts/e2e_eval.js` 的 OR 逻辑，支持 required keywords、keyword groups、forbidden keywords、最小回答长度、失败/超时记录和单调时钟延迟。

**验收标准：**

- [ ] 旧测试集可兼容，但不再“命中任一关键词即通过”；
- [ ] 每条结果记录状态、延迟、命中/缺失/禁用词和错误；
- [ ] 报告提供总体、分类、P50/P95 和失败详情；
- [ ] 存在失败或超时时退出码非零。

**验证：** 使用本地 mock HTTP 服务测试脚本，随后在服务启动时运行真实评测。

**依赖：** 无。

**预计文件：** 评测脚本、测试集兼容转换和报告 schema，控制在 5 个以内。

### Task 6：新增语音链路延迟基准

**描述：** 使用固定转写文本调用 voice-transcript 接口和流式 TTS，分别记录回答耗时、TTS 首字节、完整音频和总耗时；真实麦克风/外部数字人服务作为可选模式。

**验收标准：**

- [ ] 默认模式不依赖真实麦克风；
- [ ] 输出 P50/P95/最大值和每轮错误分类；
- [ ] 外部服务未启动时标记 skipped，不伪造结果；
- [ ] TTS 首字节和完整音频计时使用真实流读取。

**验证：** 本地 mock/真实 TTS 服务各运行一次；Node 脚本语法检查。

**依赖：** Task 5 的计时和报告格式可复用，但可独立实现。

## Phase 4：消费行为分析

### Task 7：生成官方 Excel 的可复现聚合结果

**描述：** 从 `示范景区公开资料包/景点景区旅游数据行为分析数据.xlsx` 读取行为数据，生成小型 JSON；保留 SHA256、行数、清洗计数、筛选条件和生成时间，不把原始 Excel 放入运行时数据库。

**验收标准：**

- [ ] 全量和名称/内容包含“灵山”的专项统计均可复现；
- [ ] 输出总消费、人均消费、类别结构、月度趋势、年龄段、满意度关系、停留时长和同行人数分析；
- [ ] 缺失值、非法金额和非法满意度有清洗计数；
- [ ] 生成结果不包含原始游客明细。

**验证：** 使用资料包运行聚合命令，并对固定小样本运行单元测试。

**依赖：** 无。

**预计文件：** 聚合命令/脚本、输出 schema 和测试，控制在 5 个以内。

### Task 8：增加管理员消费分析 API 和页面展示

**描述：** 增加管理员消费分析接口，读取聚合 JSON，支持全量和灵山专项范围；页面复用现有管理端图表风格，不在接口请求中解析 Excel。

**验收标准：**

- [ ] 接口有管理员鉴权；
- [ ] 返回 source metadata、summary、category breakdown、monthly trend、segments、recommendations、data quality；
- [ ] 聚合文件不存在或无数据时不返回虚构图表数据；
- [ ] 中英文文案和 API 类型同步。

**验证：** Go handler/service 测试、前端检查和构建。

**依赖：** Task 7。

**预计文件：** 后端 service/handler、前端 dashboard/API/i18n，拆分提交，单个切片控制在 5 个文件以内。

## 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| Qwen 账户或 endpoint 配置不一致 | 多模态请求失败 | base URL、model、timeout 全部环境化，先用 mock 验证 |
| 现有工作区存在用户未提交改动 | 误覆盖用户代码 | 修改前后只操作明确文件，不回退或重置工作区 |
| Excel 字段或编码变化 | 聚合结果错误 | 校验字段名、SHA256、行数和清洗计数 |
| TTS 外部服务未启动 | 无法得到真实数据 | 模拟链路和外部链路分开报告，不伪造指标 |
| 多模块变更影响现有接口 | 回归失败 | 每个 checkpoint 独立验证，最后运行完整检查 |
